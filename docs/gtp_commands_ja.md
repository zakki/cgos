# CGOS 参加者向け GTP コマンド実装ガイド

[English (英語版)](gtp_commands.md)

## TL;DR

すでに GTP 仕様を把握している方は、まず以下の要点を押さえてください。

- 必須コマンド（7つ）:  
  `list_commands`、`boardsize`、`clear_board`、`komi`、`play`、`genmove`、`quit`  
  Python版接続プログラムが起動時に検証します。1つでも欠けると接続プログラムがエラーを報告し、そのエンジンは対局できません。`list_commands` の応答には、`list_commands` 自身を含めた7つすべてを載せてください。
- 自手番側の `play` 対応（再開時に必須）:  
  通常対局中は相手の手だけが `play` で届きますが、切断後の対局再開時には、サーバーから受け取った初手からの全着手を接続プログラムが `play` に変換して再送します。そのため、エンジンは手番の色に関係なく、黒・白どちらの `play` も受け付ける必要があります。
- 残り時間管理（ほぼ必須）:  
  時間切れ負けを防ぐための `time_settings` と `time_left` も対局にはほぼ必須です。接続プログラムは両方に対応していなければ、どちらのコマンドも送信しないため、必ずセットで実装してください。

---

## この文書の範囲

CGOS では、対局サーバーが囲碁エンジンへ直接 GTP コマンドを送信するわけではありません。

```text
CGOS サーバー ──[CGOS通信プロトコル]── 接続プログラム（CGOS クライアント） ──[GTP]── 囲碁エンジン
```

CGOS サーバーから送信された対局進行メッセージを接続プログラムが受信し、必要な GTP コマンドへ変換してエンジンへ中継します。  
本稿では、囲碁エンジン側で対応すべき GTP コマンドの仕様と呼び出し順について説明します（CGOS の通信プロトコル自体は扱いません）。

> [!NOTE]
> 本書では、現在標準で利用されている Python 製接続プログラムを Python版接続プログラム、従来の接続プログラムを 旧Tcl版接続プログラム と表記して区別します。

### GTP 通信の基本原則
- 応答形式: 成功応答は `=`、失敗応答は `?` で始め、**末尾には必ず空行（連続した改行: LF LF または CRLF CRLF）を出力してください**。
- コマンド ID: 接続プログラムはコマンド ID を付与せずに送信します。
- 標準出力と標準エラー出力の分離: エンジンの診断・デバッグログを標準出力（stdout）へ混在させないでください（GTP 応答が破損します）。ログは必ず標準エラー出力（stderr）へ出力してください。

## 1. Python版接続プログラム（標準）が使用するコマンド

### 必須コマンド（対局エンジン）

| コマンド | 引数例 | 用途・説明 |
| :--- | :--- | :--- |
| `list_commands` | なし | 対応コマンド一覧を取得する。接続プログラムが起動直後に無条件で呼び出す。 |
| `boardsize <size>` | `19` | 盤のサイズを設定する。 |
| `clear_board` | なし | 盤面を初期化する。 |
| `komi <komi>` | `7.5` | コミを設定する。 |
| `play <color> <move>` | `b Q16` | 着手を盤面に反映する。通常対局では相手の手、対局再開時は初手からの全着手が送られる。 |
| `genmove <color>` | `w` | 指定された手番の着手を生成する。 |
| `quit` | なし | エンジンプロセスを終了する。 |

> [!IMPORTANT]
> 接続プログラムは起動時に `list_commands` の結果を検証します。上記コマンド（`boardsize`、`clear_board`、`komi`、`play`、`genmove`、`quit`）が 1つでも欠けていると対局を開始できません。また、`list_commands` 自身も一覧に含めて返してください。

※観戦用オブザーバー機能（GoGUI 等の接続）として動作させる場合、`genmove` は不要ですが、それ以外の必須コマンドはすべて必要です。

### オプショナルコマンド

| コマンド | 引数例 | 使用条件と用途 |
| :--- | :--- | :--- |
| `time_settings <main> 0 0` | `300 0 0` | `time_settings` と `time_left` の両方に対応している場合のみ、対局開始時に送信（単位: 秒）。末尾の `0 0` は秒読み設定なしを表す。 |
| `time_left <color> <time> 0` | `b 285 0` | 同上。自手番の着手生成直前に残り時間を通知する（単位: 秒）。末尾の `0` は石数なしを表す。 |
| `cgos-opponent_name <name>` | `KataGo` | 対応している場合のみ、対局相手の名前を通知する。 |
| `cgos-opponent_rating <rating>` | `3500.0` | 対応している場合のみ、対局相手のレーティングを通知する。 |
| `cgos-gameover <result>` | `B+Resign` | 対応している場合のみ、終局結果（`B+Resign`, `W+3.5`, `B+Time` 等）を通知する。 |
| `cgos-genmove_analyze <color>` | `b` | 対応している場合、解析情報（勝率・目数差・PV等）付きの着手生成に使用する。 |
| `kata-genmove_analyze <color> ownership true` | `b ownership true` | 上記が非対応で、このコマンドに対応している場合に使用する。 |
| `lz-genmove_analyze <color> 100000` | `b 100000` | 上記2つが非対応で、このコマンドに対応している場合に使用する。 |

- 解析コマンドの優先順位:  
  `cgos-genmove_analyze` → `kata-genmove_analyze` → `lz-genmove_analyze` の順に優先されます。対応しているもののうち最も優先順位の高いコマンドが、`genmove` の代わりに使用されます（ただし起動時の必須検査のため、`genmove` の実装自体は必須です）。解析形式の詳細は [CGOS GTP Extension for Move Analysis](gtp.md) を参照してください。
- 時間管理の条件:  
  `time_settings` と `time_left` の両方が `list_commands` に存在する場合に限り時間通知が行われます。片方のみの実装ではどちらも呼び出されません。

## 2. 旧Tcl版接続プログラムが使用するコマンド

### 必須コマンド

| コマンド | 用途 |
| :--- | :--- |
| `list_commands` | 起動時のコマンド一覧取得。 |
| `boardsize <size>` | 盤のサイズ設定。 |
| `clear_board` | 盤面の初期化。 |
| `komi <komi>` | コミ設定。 |
| `play <color> <move>` | 着手の反映。 |
| `genmove <color>` | 着手の生成。 |
| `quit` | 接続プログラムの終了時、エンジン切り替え時、エラー時のエンジン終了。 |

※旧Tcl版接続プログラムは、Python版接続プログラムと異なり、起動時にコマンド一覧を検査しません。ただし、対局進行中または終了時に実際に呼び出すため、エンジン側ではすべて実装しておく必要があります。

### オプショナルコマンド

- `time_settings <main> 0 0`
- `time_left <color> <time> 0`

※旧Tcl版は、相手情報通知（`cgos-opponent_*`）、終局通知（`cgos-gameover`）、および解析付き着手生成コマンドには対応していません。

## 3. 通常対局時の GTP コマンドシーケンス

### コマンドの流れ
1. エンジン起動直後: `list_commands` が送信される。
2. 対局開始時: 盤サイズとコミの設定（`boardsize`, `komi`, `clear_board` 等）が行われる。時間管理や相手情報に対応していれば、それらも送信される。  
   ※ルール（中国ルール、日本ルール等）を設定する GTP コマンドは送信されません。ルールは事前にエンジンの起動オプションや設定ファイル等で CGOS サーバー側の設定と一致させておく必要があります。
3. 相手の手番: 相手が着手するたびに `play` が送信される。
4. 自分の手番: 時間管理に対応していれば `time_left` が送られ、続いて `genmove`（または解析コマンド）が送信される。
5. 着手応答: エンジンは GTP 座標（`Q16` 等）、`pass`、または `resign` を返答する。
   - 注意: GTP の標準仕様に従い、**`genmove` で返した着手はエンジン自身の盤面にも即座に反映してください**。接続プログラムがその手を改めて `play` で送り返すことはありません。
6. 3〜5 を終局まで繰り返す。終局時、対応していれば `cgos-gameover` が送信される。

### 対局開始時のコマンド送信順序（差異の比較）

接続プログラムの実装によって、対局開始時の送信順が異なります。エンジンはいずれの順序で初期化されても正しく動作するようにしてください。

| 接続プログラム種別 | 送信順 |
| :--- | :--- |
| Python版（現行） | `boardsize` → `komi` → [`time_settings`] → [`cgos-opponent_name`] → [`cgos-opponent_rating`] → `clear_board` |
| 旧Tcl版 | `boardsize` → `clear_board` → `komi` → [`time_settings`] |

※`[` `]` で囲まれたコマンドは、エンジンが対応している場合のみ送信されます。

> [!IMPORTANT]
> `clear_board` は、コミや持ち時間設定をリセットせずに盤面のみをクリアする実装にしてください。Python版接続プログラムは `komi` と `time_settings` を `clear_board` の前に送信しますが、旧Tcl版接続プログラムは `clear_board` の後に `komi` を送信するためです。

### シーケンス概略図

```text
list_commands
（対局開始時の初期化: 上の表に示した接続プログラム別の順序に従う）

相手の手番: play <color> <move>
自分の手番: [time_left <color> <time> 0]
          genmove <color>
          ← = <move> (座標 / pass / resign)

（終局まで繰り返し）
[cgos-gameover <result>]
```

> [!NOTE]
> - `play` の手番は `b` または `w`、着手は `pass` または GTP 座標です。19路盤のGTP座標は、列を表す `A`〜`T`（`I` を除く）と、行を表す `1`〜`19` の組み合わせです。より小さい盤ではその部分集合を使います。
> - `resign`（投了）は `genmove` の応答として返します。エンジンが `play <color> resign` を受信することはありません。

## 4. 通信切断後の対局再開シーケンス

通信切断後に同じアカウント名で再接続した場合、CGOS サーバーは中断局の局面を復旧するため、初手からの全着手履歴を接続プログラムへ送信します。接続プログラムはエンジンに対して次の手順を実行します。

1. 上の表に示した接続プログラム別の対局開始時の初期化手順を再実行する（角括弧内のコマンドはエンジンが対応している場合のみ送信）。`clear_board` でコミや持ち時間設定がリセットされないように注意してください。
2. 保存されている初手からの全着手を、黒番・白番交互に `play b ...`, `play w ...` として順番に送信する。
3. 自分の手番の場合: サーバーが計測している現在の残り時間を `time_left` で通知し、直ちに `genmove`（または解析コマンド）を送信する。
   相手の手番の場合: 相手の次の着手が届くまで待機する。

```text
（対局開始時の初期化: 上の表に示した接続プログラム別の順序に従う）
play b <1手目>
play w <2手目>
play b <3手目>
...
自分の手番の場合:
  [time_left <color> <現在の残り秒数> 0]
  genmove <color>
相手の手番の場合:
  相手の着手を待つ
```

### 再開処理における重要注意点
- 自手番の着手も play で届く:  
  通常対局中の `play` は相手の手だけですが、再開時は盤面クリア後に**自分が打った過去の手も含めて全着手が `play` で送信されます**。エンジン自身の割り当て色に関係なく、黒・白両方の `play` を受け付けられる実装にしてください。
- 局面の完全再構築:  
  エンジン内部の探索木や履歴キャッシュに依存せず、初手からの `play` の連続適用だけで常に同一かつ合法な局面を再現できる必要があります。
- 時間の経過と残り時間:  
  過去の手番の消費時間は再生されません。現在の手番の直前に「いま残っている実時間」のみが `time_left` で届きます。切断中もサーバー上の対局時計は進んでいるため、切断前にエンジン側で記録した残り時間を使わないでください。
- 自動復帰時の挙動:  
  旧Tcl版接続プログラムは、エンジンプロセスを維持したまま、一定時間待機した後に自動再接続します。Python版接続プログラムは、障害が発生した経路に応じて、既存のエンジンを維持したまま再接続するか、外周ループによってエンジンプロセスを再起動します。新しいエンジンを起動した場合は `list_commands` から初期化をやり直し、CGOSへの再接続後に上記の手順で局面を再構築します。

## 5. 最小実装チェックリスト

エンジンを CGOS に接続する前に、以下の項目を満たしているか確認してください。

- [ ] `list_commands` が、`list_commands` 自身および必須コマンド（`boardsize`, `clear_board`, `komi`, `play`, `genmove`, `quit`）をすべて含んだ一覧を返すこと
- [ ] すべての GTP 応答が `=`（エラー時は `?`）で始まり、末尾が空行（連続した改行: LF LF または CRLF CRLF）で終了していること
- [ ] プロセスを再起動することなく、`boardsize`, `clear_board`, `komi` を何局でも繰り返し受け付けて新規対局を開始できること
- [ ] `clear_board` がコミや持ち時間設定をリセットせずに盤面をクリアすること
- [ ] `play` コマンドで黒（`b`）・白（`w`）双方の着手、および `pass` を受け付けられること
- [ ] `genmove` で返した着手を、エンジン自身の内部盤面にも即座に反映していること（接続プログラムから `play` で送り返されないため）
- [ ] `clear_board` 後に初手からの全着手が連続して `play` された場合でも、盤面を正しく再現できること
- [ ] 時間管理を有効にする場合は、`time_settings` と `time_left` の両方を実装していること
- [ ] 診断・デバッグログ出力は標準出力（stdout）に出さず、標準エラー出力（stderr）に出力していること
